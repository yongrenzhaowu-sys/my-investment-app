# バックテスト計画: 週次リバランス・セクターモメンタム戦略

**作成日**: 2026-03-03
**目的**: 過去3ヶ月間で週次リバランスを行った場合のリターンを検証

---

## 要件

### バックテスト期間
- **開始日**: 2025-12-02（約3ヶ月前）
- **終了日**: 2026-03-02（最新）
- **リバランス頻度**: 週次（毎週月曜日、または営業日の場合は翌営業日）

### 戦略ルール
1. 毎週月曜日（または次の営業日）に推奨銘柄を再計算
2. 推奨銘柄TOP 10を均等配分（各10%）またはボラティリティ調整ウェイト
3. リバランス時のコスト：0.1%（片道）を仮定
4. 初期資金：1,000,000円

### 評価指標
- 累積リターン（%）
- 年率換算リターン
- シャープレシオ
- 最大ドローダウン（MDD）
- 勝率（週次リターンが正の割合）
- ベンチマーク比較（TOPIX or 均等配分）

---

## 実装手順

### 1. データ取得
- J-Quants APIから過去4ヶ月分のデータを取得（計算用に余裕を持たせる）
- 期間：2025-11-01 〜 2026-03-02

### 2. 週次リバランス日の特定
- 毎週月曜日をリバランス日として設定
- 営業日でない場合は次の営業日
- リスト化：[2025-12-02, 2025-12-09, 2025-12-16, ...]

### 3. 各リバランス日での処理
- その時点での推奨銘柄TOP 10を計算
- ポジションサイズを決定（ボラティリティ調整 or 均等配分）
- 前週のポジションと比較し、売買を記録

### 4. リターン計算
- 各週のリターンを計算
- リバランスコスト（0.1% × ターンオーバー）を差し引く
- 累積リターンを計算

### 5. パフォーマンス評価
- 各種指標を計算
- グラフ生成（累積リターン推移）
- ベンチマークとの比較

## 想定される課題

### データ不足
- 過去3ヶ月のデータが全て揃っていない可能性
- 対策：ローカルparquetファイルを使用（2026-01-22まで）+ API（01-23以降）

### 計算時間
- 週次で戦略を再実行するため、時間がかかる
- 対策：並列化、キャッシュ

### ルックアヘッドバイアス
- リバランス日時点で利用可能なデータのみを使用
- 対策：asof_dateを厳密に管理

---

## 検証項目

- [ ] データ期間が十分か（3ヶ月 = 約12週間）
- [ ] リバランス日が正しく特定されているか
- [ ] 各週のリターン計算が正確か
- [ ] コストが正しく差し引かれているか
- [ ] ベンチマークとの比較が妥当か
