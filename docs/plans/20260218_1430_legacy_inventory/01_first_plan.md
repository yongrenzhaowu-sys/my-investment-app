# legacy/projects 棚卸し計画

**作成日時**: 2026-02-18 14:30
**目的**: legacy/projects配下の過去資産(.ipynb)をカタログ化し、再利用可能にする

## 前提条件

### 確認事項（ユーザー回答済み）
1. **分析深さ**: メタデータ＋主要ファイル（トップ20）のみ詳細分析
2. **優先基準**: ファイル名から推定される機能（backtest/feature/preprocess/signal等）
3. **status判定**: 自動判定（更新日・サイズ・参照から推定）

### 対象範囲
- **対象ディレクトリ**: `legacy/projects/`
- **ファイル構成**: 全て.ipynbファイル（pyファイルは0件）
- **総ファイル数**: 約90個のipynbファイル
- **プロジェクト分類**: フォルダではなく、ファイル名パターンで分類
  - FF5関連（FF5モデル、FF5バックテスト等）
  - 四半期成長率関連
  - 月足線形モデル関連
  - ロングオンリー戦略関連
  - その他（バリュー、レバレッジ、期ズレ等）

## 作業ステップ

### Step 1: メタデータ収集（全ファイル）
- [ ] 全ipynbファイルの基本情報を取得
  - ファイル名
  - ファイルサイズ（バイト）
  - 最終更新日
  - セル数（ipynb構造から）
- [ ] ファイル名パターンから戦略カテゴリを分類
  - FF5系、四半期系、月足系、ロングオンリー系、その他

### Step 2: 再利用候補トップ20抽出
優先基準（ファイル名から推定される機能）に基づき、以下のキーワードを含むファイルを優先：
- `backtest` / `バックテスト`
- `feature` / `特徴`
- `preprocess` / `前処理`
- `signal` / `シグナル`
- `model` / `モデル`
- `実装` / `実行` / `完成`
- `最終` / `保存用`

さらに以下も考慮：
- ファイルサイズ（大きい = 複雑な処理の可能性）
- 最終更新日（新しい = 現役の可能性）

### Step 3: トップ20の詳細分析
選定された20ファイルについて：
- [ ] ipynbを読み込んでセル内容を確認
- [ ] import文から依存ライブラリを抽出
- [ ] 主要な処理内容を推定（データ取得/前処理/バックテスト/可視化等）
- [ ] コメント・Markdownセルから目的・仮説を抽出

### Step 4: status自動判定
各候補に対して以下のルールで判定：
- **keep**:
  - 最終更新が2026年1月以降
  - かつファイル名に「完成」「最終」「実装」等を含む
  - かつサイズが100KB以上
- **refactor**:
  - 最終更新が2025年12月～2026年1月
  - かつサイズが50KB以上
  - または「モデル」「バックテスト」を含む
- **archive**:
  - 最終更新が2025年12月以前
  - かつサイズが50KB未満
  - またはファイル名が「Untitled」「検証用」「作業中」

### Step 5: 移植先提案（refactor候補のみ）
- `src/`: 汎用ライブラリ・モジュール（データ取得、前処理、特徴量計算）
- `scripts/`: 単発実行スクリプト（バックテスト実行、レポート生成）
- `analyses/`: 分析プロジェクト（仮説検証、パラメータ最適化）
