## 戦略の定義

### 基本戦略: 小型株 × 高成長率 × 3ヶ月リバランス

**ユニバース**:
- 全銘柄（J-Quants API経由で取得可能な銘柄）

**スクリーニング条件**:
1. **時価総額**: 下位25%（Q1、小型株）
2. **カスタム成長率**: 上位25%（Q4、高成長）
3. **四半期決算データが存在**（直近4四半期のデータあり）

**リバランス**:
- **頻度**: 3ヶ月ごと
- **タイミング**: 毎月月初（1月、4月、7月、10月）
- **ウェイト**: 等ウェイト（各銘柄に均等配分）

**エントリー/エグジット**:
- **エントリー**: リバランス日の翌営業日の寄り値
- **エグジット**: 次回リバランス日の翌営業日の寄り値

### 3. バックテストロジック

#### ステップ1: リバランス日の決定
```python
rebalance_dates = pd.date_range('2017-04-01', '2025-07-01', freq='3MS')
# 3MS = 3ヶ月ごとの月初（1月、4月、7月、10月）
```

#### ステップ2: 各リバランス日での銘柄選定
```python
for rebalance_date in rebalance_dates:
    # その時点で利用可能な最新の決算データを使用
    available_data = df[df['disclosed_date'] < rebalance_date]

    # 時価総額と成長率の四分位を再計算
    available_data['marketcap_quartile'] = pd.qcut(...)
    available_data['growth_quartile'] = pd.qcut(...)

    # 小型株（Q1）× 高成長率（Q4）を選定
    selected = available_data[
        (available_data['marketcap_quartile'] == 'Q1') &
        (available_data['growth_quartile'] == 'Q4')
    ]
```

#### ステップ3: ポートフォリオのリターン計算
```python
# 等ウェイトポートフォリオ
portfolio_return = selected['return_3M'].mean()
```

#### ステップ4: 累積リターンの計算
```python
cumulative_returns = (1 + portfolio_returns).cumprod()
```

### 4. 評価指標

#### 必須指標

## 未来参照の防止（重要）

### ルール
1. ✅ **リバランス日時点で利用可能な決算データのみ使用**
   - `disclosed_date < rebalance_date`

2. ✅ **エントリー価格はリバランス日の翌営業日**
   - リバランス日当日の価格は使用しない
   - 実務上、リバランス日に銘柄選定 → 翌日に発注

3. ✅ **時価総額・成長率の四分位は各リバランス日で再計算**
   - 過去全体での四分位ではなく、その時点での四分位

4. ✅ **カスタム成長率は開示日時点のデータで計算**
   - 未来の決算データは使用しない

## リバランス頻度の比較

### 検証すべきパターン

| 頻度 | リバランス周期 | 取引コスト（年間） | 期待効果 |
|------|---------------|-------------------|---------|
| **月次** | 1ヶ月 | 高（年12回） | 最新情報を反映 |
| **四半期** | 3ヶ月 | 中（年4回） | 効果最大 |
| **半年** | 6ヶ月 | 低（年2回） | 効果減衰 |

**仮説**:
- 四半期（3ヶ月）が最適
- 月次は取引コストで利益が相殺される可能性
- 半年は効果が減衰（既存分析で+1.06%のみ）

## 実装上の注意点

### 1. リバランス日の決定
- 月初（1日）を基準
- 営業日でない場合は翌営業日

### 2. 決算データの鮮度
- リバランス日時点で「最新」の決算データを使用
- 同一銘柄で複数の決算がある場合は最新のものを採用

### 3. 銘柄数の変動
- 各リバランス日で選定される銘柄数は異なる
- 極端に少ない場合（例：5銘柄未満）は警告

### 4. 欠損データの扱い
- 3ヶ月後の株価が存在しない場合は除外
- 上場廃止銘柄は-100%のリターンとして扱う（実装により異なる）
