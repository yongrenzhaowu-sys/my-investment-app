# ナレッジ: 週次リバランス・セクターモメンタム戦略の実証結果

**作成日**: 2026-03-03 10:30
**対象期間**: 2025-12-02 〜 2026-03-02（3ヶ月）
**戦略**: セクターモメンタム × ボラティリティ逆数ウェイティング × 週次リバランス

---

## 核心的発見

### 1. 戦略の有効性
**3ヶ月で20.27%のリターン**（年率換算109.25%）を達成。

- シャープレシオ1.55は十分に高い（一般的に1.0以上が優秀）
- 勝率53.8%は期待値がプラスであることを示す
- 最大ドローダウン15.48%は許容範囲内

**結論**: 短期モメンタム × セクターフィルター × リスク調整は機能している。

### 2. リバランス頻度の影響
週次リバランスによる取引コストの影響:

- 平均ターンオーバー: 約0.5〜1.0程度（全体の50〜100%入れ替え）
- 平均取引コスト: 約0.05〜0.1%/週
- グロスリターンとネットリターンの差: 小さい

**結論**: 週次リバランスのコストは許容範囲内。月次との比較が必要。

### 3. セクター集中のリスク
バックテスト期間中のTOP3セクター:

1. 非鉄金属（3500）
2. 精密機器（3750）
3. 電気機器（3650）

これらのセクターが好調な期間だったため、高リターンが実現。

**リスク**: セクター逆回転時の大幅下落の可能性。

## 実装上の重要ポイント

### タイミング設計
```
t週月曜日終値 → 推奨銘柄計算（その時点で利用可能な60日分データ）
t週月曜日終値 → シグナル確定
t+1日（火曜日）始値 → 約定（実際の購入）
t+1週月曜日終値 → 次回リバランス
```

**ルックアヘッドバイアス防止**: 各リバランス日時点で利用可能なデータのみを使用。

### データ要件
- **最低期間**: 60日（20日リターン + 20日SMA + ATR14計算のため）
- **推奨期間**: 120日（余裕を持たせる）
- **営業日判定**: data_datesから利用可能な日付を特定

### コスト計算
```python
turnover = Σ|new_weight - old_weight|
cost_pct = turnover × 0.001  # 0.1% one-way
net_return = gross_return - cost_pct
```

初回リバランスはターンオーバー=0（全て新規購入）。

## パフォーマンス分析

### 週次リターン分布
- 最大週次リターン: プラス側で約+10%超
- 最大週次損失: マイナス側で約-10%程度
- 中央値: プラス圏

**観察**: 正規分布ではなく、右側（プラス）にやや偏り。

### ドローダウン特性
- 最大DD: 15.48%
- DD回復: 比較的早い（数週間以内）
- DD発生頻度: 2〜3回程度

**観察**: 一時的な調整はあるが、トレンドは上向き。

### 勝率とペイオフレシオ
- 勝率: 53.8%（13週中7週がプラス）
- 平均勝ち: 推定+5〜8%
- 平均負け: 推定-3〜5%
- ペイオフレシオ: 約1.2〜1.5

**観察**: 勝率はやや高く、ペイオフレシオも良好。

## 限界と注意点

### 1. サンプルサイズ不足
- **期間**: 3ヶ月のみ（13週分）
- **統計的有意性**: 限定的
- **必要**: 最低1年（52週）、理想的には3年以上

### 2. 市場環境依存
- **期間特性**: 2025年12月〜2026年3月は全体的に強気
- **セクター偏り**: 非鉄金属・精密機器が急騰
- **弱気相場での検証**: 未実施

### 3. 生存者バイアス
- **上場廃止**: 考慮していない
- **データ品質**: J-Quantsの調整済み価格を信頼
- **欠損値処理**: 単純除外

### 4. コストモデルの簡易性
- **スリッページ**: 未考慮
- **流動性コスト**: 未考慮（平均出来高30M円以上でフィルタのみ）
- **税金**: 未考慮

## 再現可能な知見

### ベストプラクティス

1. **データ取得**:
   - J-Quants API使用（最新データ）
   - ローカルキャッシュ優先（同日再実行時）
   - 60日以上の履歴を確保

2. **リバランス日の特定**:
   ```python
   mondays = pd.date_range(start=start_dt, end=end_dt, freq='W-MON')
   # 営業日に調整（月曜〜金曜の最初の営業日）
   for monday in mondays:
       for offset in range(5):
           candidate = monday + timedelta(days=offset)
           if candidate in available_dates.values:
               rebalance_dates.append(candidate)
               break
   ```

3. **リターン計算**:
   ```python
   start_price = period_data.iloc[0]['AdjC']
   end_price = period_data.iloc[-1]['AdjC']
   stock_return = (end_price / start_price - 1.0) * 100.0
   ```

4. **ターンオーバー計算**:
   ```python
   turnover = sum(abs(new_weight - old_holdings.get(code, 0.0))
                  for code, new_weight in new_holdings.items())
   ```

### 避けるべき落とし穴

1. **営業日の仮定**: 単純に7日ごとではなく、実際の営業日カレンダーを使用
2. **欠損データ**: 銘柄が途中で消える場合の処理（continue でスキップ）
3. **ゼロ除算**: start_price, total_weight が0の場合のチェック
4. **型不一致**: Code列は常にstring型に統一
