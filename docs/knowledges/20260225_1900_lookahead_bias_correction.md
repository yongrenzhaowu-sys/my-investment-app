## 発見の経緯

### 1. 初回バックテスト（バイアスあり）

**戦略**: 小型株×高成長率（月次エントリー）
**結果**: 年率+56.38%、シャープレシオ2.440

```python
# その月に決算発表があった銘柄を取得
disclosed_this_month = df_growth[df_growth['year_month'] == current_month]

# その決算データでスクリーニング
latest_data = disclosed_this_month.groupby('code').last()

# エントリー: 月初
entry_date = current_month_start  # 例: 2017-07-01
```

### 2. ユーザーの指摘

> **「イベントドリブン戦略はルックアヘッドバイアス入っていないか？そもそも決算発表日からの購入が無理ではないか？」**

### 3. 問題の特定

**ロジックの問題**:
- 2017年7月に決算発表があった銘柄について
- **その7月の決算データ**を使ってスクリーニング
- しかしエントリーは**7月1日（月初）**
- → 7月1日時点では、7月の決算はまだ発表されていない！

**物理的に不可能な操作** = 未来参照バイアス

## 修正方法

### 修正前のロジック（間違い）

```python
# その月に決算発表があった銘柄を取得
disclosed_this_month = df_growth[df_growth['year_month'] == current_month]

# その決算データでスクリーニング ← 未来参照！
latest_data = disclosed_this_month.groupby('code').last()

# エントリー: 月初
entry_date = current_month_start  # 例: 2017-07-01
```

**問題点**:
1. `current_month` (2017-07) の決算データを取得
2. しかし、7月の決算発表は7月1日より後（例: 7月15日、7月31日など）
3. 7月1日時点では7月の決算データは利用不可能
4. → **未来のデータを使って過去の意思決定をしている**

### 修正後のロジック（正しい）

```python
# 月初時点で利用可能なデータのみ（disclosed_date < 月初）
current_month_start = pd.Timestamp(f"{current_month}-01")
available_data = df_growth[df_growth['disclosed_date'] < current_month_start]

# 前回までの決算データでスクリーニング ← 正しい！
latest_data = available_data.groupby('code').last()

# エントリー: 月初
entry_date = current_month_start
```

**正しい点**:
1. `disclosed_date < current_month_start` で、月初より前のデータのみ取得
2. 月初時点で実際に利用可能なデータのみを使用
3. 未来参照なし

## ルックアヘッドバイアスのパターン

### パターン1: 同時点データの使用

**間違い**:
```python
# その日の終値でシグナル確定
signal = df[df['date'] == today]

# その日の終値で購入 ← 実際には翌日しか買えない
entry_price = df.loc[today, 'close']
```

**正しい**:
```python
# t日の終値でシグナル確定
signal = df[df['date'] == today]

# t+1日の始値で購入
entry_price = df.loc[tomorrow, 'open']
```

### パターン2: 未来のデータでフィルタリング

**間違い**:
```python
# その月に決算があった銘柄のデータでスクリーニング
disclosed_this_month = df[df['year_month'] == current_month]
selected = screen(disclosed_this_month)  # 未来参照！
```

**正しい**:
```python
# 月初時点で利用可能なデータのみでスクリーニング
available_data = df[df['disclosed_date'] < current_month_start]
selected = screen(available_data)  # OK
```

### パターン3: 全期間での四分位計算

**間違い**:
```python
# 全期間でのデータで四分位を計算
df['quartile'] = pd.qcut(df['value'], q=4)

# その時点の四分位でフィルタリング ← 未来参照！
selected = df[(df['date'] == today) & (df['quartile'] == 'Q1')]
```

**正しい**:
```python
# その時点で利用可能なデータのみで四分位を計算
available = df[df['date'] <= today]
available['quartile'] = pd.qcut(available['value'], q=4)

# 各時点ごとに再計算
selected = available[available['date'] == today]
```

## チェックリスト

バックテスト実装時に必ず確認すべき項目：

### ✅ タイミングチェック

1. **シグナル生成のタイミング**
   - [ ] t日の情報でt+1日以降にエントリー？
   - [ ] 同日エントリーしていないか？

2. **データの利用可能性**
   - [ ] その時点で実際に利用可能なデータのみ使用？
   - [ ] 未来のデータを参照していないか？

3. **四分位・ランキング計算**
   - [ ] 各時点ごとに再計算？
   - [ ] 全期間での計算を使い回していないか？

4. **価格データ**
   - [ ] t日終値でシグナル → t+1日始値/終値でエントリー？
   - [ ] t日終値でシグナル → t日終値でエントリー（NG）

### ✅ ロジックレビュー
