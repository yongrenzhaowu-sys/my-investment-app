## 学んだこと・注意点

### 1. Git管理の目的
**メリット**:
- ✅ 変更履歴の追跡（いつ、誰が、何を変更したか）
- ✅ 誤削除・誤編集時の復旧
- ✅ 実験的な変更の安全な実施（ブランチ）
- ✅ チーム間でのコード共有

**注意点**:
- ❌ 機密情報をコミットしない（.gitignoreで防止）
- ❌ 大容量ファイルをコミットしない（リポジトリ肥大化）
- ❌ 意味のないコミットを避ける

### 2. .gitignoreの重要性
**役割**:
- Git管理から除外するファイル/ディレクトリを指定
- 誤って機密情報をコミットすることを防止

**パターン**:
- `*.env`: 全ての.envファイル
- `data/`: dataディレクトリ全体
- `__pycache__/`: Python一時ファイル

**確認方法**:
```bash
# 除外されているか確認
git status --ignored
```

### 3. LF vs CRLF警告
**警告内容**:
```
warning: in the working copy of '<file>', LF will be replaced by CRLF the next time Git touches it
```

**意味**:
- Unix/Linux: LF（改行）
- Windows: CRLF（キャリッジリターン+改行）
- Gitが自動変換することの警告（機能的には問題なし）

**対処**（必要に応じて）:
```bash
# 自動変換を無効化
git config --global core.autocrlf false
```

### 4. コミットメッセージのベストプラクティス
**良い例**:
```
Fix authentication bug in login flow

The bug was caused by expired refresh token not being handled correctly.
Now the system automatically fetches a new token when the old one expires.

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>
```

**悪い例**:
```
fix bug
```

### 5. legacy/の扱い
**CLAUDE.md制約**:
> legacy/projects/ 配下は原本として扱う。編集・移動・削除は禁止（参照のみ）

**Git対応**:
- `.gitignore`で`legacy/`全体を除外
- 原本データの変更を防止
- バージョン管理の必要なし（読み取り専用）

### 6. data/の扱い
**容量**: 113MB（現在）

**方針**:
- `data/raw/`, `data/curated/`, `data/fetched/`: Git管理外
- 理由: 大容量、頻繁に変更、再生成可能

**代替策**（将来的に検討）:
- DVC（Data Version Control）でデータバージョン管理
- クラウドストレージ（S3, GCS等）に保存
