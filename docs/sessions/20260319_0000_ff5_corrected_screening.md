## 🎯 実施内容

### 1. 調整済み株価の修正（CRITICAL）

**問題発見**
- 取得データの`AdjC`列が実際には調整されていない（`AdjC = C`）
- 株式分割等の影響が反映されず、極端なリターン値（+3,273%）が発生

**修正内容**
```python
# 修正前（誤り）
df_prices['Price'] = df_prices['AdjC']  # AdjC = C（調整なし）

# 修正後（正しい）
df_prices['AdjC_Correct'] = df_prices['C'] * df_prices['AdjFactor']
df_prices['Price'] = df_prices['AdjC_Correct']
```

**重複データの除外**
```python
# 同じCode×Dateで最も取引量が多いレコードを採用
df_prices = df_prices.sort_values(['Code', 'Date', 'Vo'], ascending=[True, True, False])
df_prices = df_prices.drop_duplicates(subset=['Code', 'Date'], keep='first')
# 結果: 2,875レコード除外
```

## 💡 重要な教訓

### 1. 調整済み株価の検証は必須
J-Quants APIの`AdjC`列は調整されていない可能性があるため、必ず以下を確認：
```python
# AdjFactorが1.0以外のレコードを確認
df_prices[df_prices['AdjFactor'] != 1.0].head()

# 正しい調整を適用
df_prices['AdjC_Correct'] = df_prices['C'] * df_prices['AdjFactor']
```

### 2. 重複データの除外
同じCode×Dateで複数レコードが存在する場合：
```python
# 最も取引量が多いレコードを採用
df_prices = df_prices.sort_values(['Code', 'Date', 'Vo'], ascending=[True, True, False])
df_prices = df_prices.drop_duplicates(subset=['Code', 'Date'], keep='first')
```

### 3. 異常値の確認
スクリーニング結果で極端な値（+1,000%超）が出た場合、データの品質を疑う。
