## 🔍 問題の原因

### 根本原因: INV_Growthが全て0.0000

**元のロジック**（間違い）:
```python
# 各銘柄の「最新」財務データを取得
latest_fins = df_fins.sort_values('DiscDate').groupby('Code').last().reset_index()

# 月次データとマージ
month_end = month_end.merge(latest_fins, on='Code', how='left')

# INV_Growth計算
month_end['TA_Prev'] = month_end.groupby('Code')['TA'].shift(4)
month_end['INV_Growth'] = (month_end['TA'] - month_end['TA_Prev']) / month_end['TA_Prev']
```

**問題点**:
- 各銘柄の「最新」財務データを全期間で使い回している
- そのため、`TA`（総資産）が常に同じ値になる
- `TA - TA_Prev = 0` → `INV_Growth = 0`

---

## 🔧 修正の経過

### 修正版1（calculate_ff5_momentum_full_fixed.py）

**方針**: 各時点で利用可能な財務データを使用

**結果**:
- ✅ CMAファクター計算成功: -4.19%, SR -0.62
- ❌ 対象銘柄数が大幅減少: 3,729銘柄 → 964銘柄
- ❌ INV_Growth有効銘柄数が少ない: 23～425銘柄

**問題点**:
- 各月末時点で開示済みの財務データのみを使用したため、多くの銘柄が除外
- INV_Growth計算に4四半期分のデータが必要だが、データ不足

---

### 改善版（calculate_ff5_momentum_improved.py）✅

**改善点**:
1. **財務データの利用可能性を緩和**
   - 月末時点 → 月末の1ヶ月前までに開示されたデータ
   - ルックアヘッドバイアスは防止しつつ、より多くの銘柄をカバー

2. **INV_Growth計算方法の改善**
   - 前年同期比（4四半期前が必要） → 直近2期間の成長率
   - 年率換算: `INV_Growth = (TA - TA_Prev) / TA_Prev * (365 / Days)`
   - 異常値除外: -100%～+100%の範囲に制限

**結果**:
- ✅ CMAファクター: **+4.97%, SR 1.04**（プラス転換！）
- ✅ INV_Growth有効銘柄数: 約780銘柄（16倍に増加）
- ✅ 対象銘柄数: 約1,000銘柄（安定）

## 💡 CMAファクターの解釈

### CMA（Conservative Minus Aggressive）= +4.97%

**意味**:
- 保守的な投資を行う企業（総資産の増加率が低い）が、アグレッシブな投資を行う企業（総資産の増加率が高い）をアウトパフォーム

**解釈**:
- 日本市場では、積極的な設備投資よりも、堅実な経営が評価される傾向
- 無理な拡大投資を避け、既存事業の効率化を重視する企業が好まれる
- リスク回避的な市場環境を反映

**投資戦略への示唆**:
- 総資産成長率が低い企業（Conservative）をロングする戦略が有効
- ただし、シャープレシオは1.04と中程度なので、単独戦略よりも他ファクターとの組み合わせが推奨

## 🎓 学び

### 1. ルックアヘッドバイアスの微妙なバリエーション

**発見**: 「最新財務データ」を全期間で使い回すこともルックアヘッドバイアスの一種

**教訓**: 各時点で利用可能なデータのみを使用する必要がある

**実装**:
```python
# ❌ 間違い: 最新財務データを使い回し
latest_fins = df_fins.groupby('Code').last()
month_end = month_end.merge(latest_fins, on='Code')

# ✅ 正しい: 各時点で利用可能なデータを使用
for month_end_date in month_ends:
    available_fins = df_fins[df_fins['DiscDate'] <= month_end_date - timedelta(days=30)]
    latest = available_fins.groupby('Code').last()
```

---

### 2. データ制約とファクター計算のトレードオフ

**課題**: より厳密なルックアヘッドバイアス防止 vs より多くの銘柄カバー

**解決策**:
- 「月末の1ヶ月前まで」という緩和ルール
- ルックアヘッドバイアスは防止しつつ、実務的なカバレッジを確保

---

### 3. INV_Growth計算の柔軟性

**問題**: 前年同期比（4四半期前）が必要 → データ不足で多くの銘柄が除外

**解決**: 直近2期間の成長率を年率換算
```python
# 1期前のTA
df_fins['TA_Prev'] = df_fins.groupby('Code')['TA'].shift(1)

# 期間の長さを計算
df_fins['Days'] = (df_fins['CurPerEn'] - df_fins['CurPerEn_Prev']).dt.days

# 年率換算
df_fins['INV_Growth'] = (TA - TA_Prev) / TA_Prev * (365 / Days)
```
