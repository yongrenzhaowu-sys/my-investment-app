## 主要な技術的解決策

### 1. J-Quants API V2の正しいパラメータ

**間違い**:
```python
params = {'from': '2021-03-01', 'to': '2021-03-31'}
```

**正しい**:
```python
params = {'date': '20210301'}  # YYYYMMDD形式、1日ずつ
```

---

### 2. 途中保存機能の実装

**実装内容**:
1. **100日ごとに保存**: `prices_partial_YYYYMMDD.parquet`
2. **進捗状態を記録**: `fetch_progress.json`（取得済み日付リスト）
3. **再開時に自動スキップ**: 取得済み日付は処理しない
4. **完了後にクリーンアップ**: 途中保存ファイルを自動削除

**コード例**:
```python
def save_intermediate_data(data_list, phase, date_str):
    """途中経過データを保存"""
    df = pd.concat(data_list, ignore_index=True)
    path = OUTPUT_DIR / f"{phase}_partial_{date_str}.parquet"
    df.to_parquet(path, index=False)

def load_progress():
    """進捗状態を読み込み"""
    if PROGRESS_FILE.exists():
        with open(PROGRESS_FILE, 'r') as f:
            return json.load(f)
    return {'prices_completed_dates': [], ...}
```

**メリット**:
- 中断しても安全に再開可能
- 取得済みデータが失われない
- APIリクエストの無駄がない

## 💡 学び

### 1. J-Quants API V2は日付単位でのみ取得可能

**教訓**: 範囲指定（`from`/`to`）ではなく、1日ずつ `date` パラメータで取得

**影響**:
- 5年間のデータ取得に約60分必要
- レート制限（1リクエスト/秒）が厳しい

---

### 2. 長時間タスクには途中保存機能が必須

**教訓**: 60分以上かかる処理は、途中保存なしでは危険

**実装のポイント**:
- 定期的な保存（100日ごと）
- 進捗状態の記録（JSON）
- 再開時の自動スキップ
- 完了後のクリーンアップ

---

### 3. Windows環境でのエンコーディング注意

**教訓**: cp932環境では特殊文字（Unicode）を避ける

**対策**:
- すべてASCII文字を使用
- 日本語はUTF-8で保存（ファイル）、表示はASCII（コンソール）
