### Phase 2: J-Quants API V2統合デバッグ（14:30-15:10）

#### 問題1: 403 Forbidden エラー（株価データ）

**原因**: エンドポイントURLが間違っている
- ❌ `/bars/daily`
- ✅ `/equities/bars/daily`

**解決**: エンドポイント修正

#### 問題2: 銘柄コードの形式

**原因**: J-Quants APIは4桁コードを期待、アプリは5桁で入力
- 入力: `72030`（5桁）
- API: `7203`（4桁）

**解決**: APIリクエスト時に4桁に変換（`code[:4]`）

#### 問題3: データが0件

**原因**:
1. 銘柄コードでフィルタリングしていない
2. 日付範囲が今日の日付（データなし）

**解決**:
1. Code列でフィルタリング追加
2. `to_date=None`の場合、APIに`end_dt`を渡さない

#### 問題4: yfinanceの列構造エラー

**原因**: yfinanceのバージョンによる列数の違い

**解決**: MultiIndexと通常Indexの両方に対応

#### 問題5: 財務データ 403 Forbidden

**原因**: エンドポイント名が V1 → V2 で変更されている
- ❌ `/fins/statements`（V1）
- ✅ `/fins/summary`（V2）

**解決**: エンドポイントを `/v2/fins/summary` に変更

#### 問題6: 型変換エラー

**原因**: Sales と OP が文字列型
```
unsupported operand type(s) for /: 'str' and 'str'
```

**解決**: `pd.to_numeric()` で数値変換

## J-Quants API V2 仕様（完全版）

### 認証
- ヘッダー: `x-api-key`
- 値: APIキー（有効期限なし）

### 株価データ
- エンドポイント: `/v2/equities/bars/daily`
- パラメータ: `code=7203`, `start_dt=20260310`（`end_dt`はオプション）
- レスポンス: `{"data": [...]}`
- 列: `Date`, `Code`, `AdjC`（調整済み終値）など

### 財務データ
- エンドポイント: `/v2/fins/summary`
- パラメータ: `code=7203`
- レスポンス: `{"data": [...]}`
- 主要列:
  - `Sales`: 売上高
  - `OP`: 営業利益
  - `NP`: 純利益
  - `EPS`: 1株あたり利益
  - `CurPerEn`: 会計期間終了日
  - `DiscDate`: 開示日

### 銘柄情報
- エンドポイント: `/v2/listed/info`
- パラメータ: `code=7203`
- レスポンス: `{"data": [...]}`
- 列: `Code`, `CompanyName`, `MarketCode`など

## 技術的な学び

### 1. J-Quants API V1 → V2 移行の罠
- エンドポイント名が変更（`/fins/statements` → `/fins/summary`）
- レスポンス形式統一（`"data"`キー）
- 列名が短縮（`OperatingProfit` → `OP`, `NetSales` → `Sales`）

### 2. データ型の注意点
- APIレスポンスの数値が文字列型の場合がある
- `pd.to_numeric(errors='coerce')` で安全に変換

### 3. 日付データの遅延
- 株価データは1〜2日遅れ
- `to_date=None`でAPIに最新データを任せる

### 4. Streamlitのエラーハンドリング
- データ取得失敗でも画面を表示
- 部分的なエラーは警告表示
