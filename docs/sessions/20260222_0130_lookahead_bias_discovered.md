## 問題の詳細

### 元のスクリプトのロジック（間違い）

```
1. 2017-10-02時点で銘柄を選択
2. スコアデータ（disclosed_date <= 2017-10-02）を取得
3. return_6Mで銘柄をソート
4. 上位20銘柄を購入

【問題点】
- return_6Mは、2017-10-02から未来6ヶ月（2018-04頃まで）のリターン
- つまり、「未来のリターンが高い銘柄」を選択している
- 実運用では絶対に不可能
```

### なぜこうなったのか

**推測される原因**:
1. prediction_scores.csvを生成する際、各開示日時点での**未来のリターン**を計算した
2. 本来は「予測精度の検証」のために作成されたデータ
3. しかし、バックテストで誤って使用してしまった

## 年率+34.88%の真相

### なぜ異常に高いリターンが出たのか

1. **未来のリターンを使用**
   - 「未来6ヶ月で最も上がる銘柄」を選択していた
   - これは「タイムマシン」で未来を見ているのと同じ

2. **完璧な情報**
   - 実際の投資では、どの銘柄が上がるか分からない
   - しかし、このバックテストでは「正解」を知っていた

3. **実運用では不可能**
   - リバランス日時点では、未来のリターンは分からない
   - したがって、+34.88%は達成不可能

## 正しいアプローチ

### return_6Mを正しく再計算

**必要な処理**:
1. 各開示日時点での**過去6ヶ月のリターン**を計算
2. prediction_scores.csvを正しく再生成
3. バックテストを再実行

**計算方法**:
```python
# 正しい方法（過去のリターン）
disclosed_date = 2017-10-02
price_6m_before = price at (2017-10-02 - 180days)
price_at_disclosed = price at 2017-10-02
return_6M = (price_at_disclosed - price_6m_before) / price_6m_before

# 間違った方法（未来のリターン）- 現在のprediction_scores.csv
disclosed_date = 2017-10-02
price_at_disclosed = price at 2017-10-02
price_6m_after = price at (2017-10-02 + 180days)  # ❌ 未来！
return_6M = (price_6m_after - price_at_disclosed) / price_at_disclosed  # ❌ ルックアヘッド！
```

## 学び

### 1. バックテストの検証は必須

- 異常に高いリターン（年率+30%超）は疑うべき
- 必ずルックアヘッドバイアスをチェック

### 2. データの出所を確認

- 外部データ（prediction_scores.csv）を使用する場合、生成方法を確認
- 特に「予測」「リターン」などの列は要注意

### 3. 複数のアプローチで検証

- 新しいスクリプトが大損失になった時点で、元のスクリプトを疑うべきだった
- ユーザーの指摘が正しかった

### 4. シンプルな戦略の価値

- 複雑な戦略ほど、バグやバイアスが入り込みやすい
- シンプルな戦略の方が信頼性が高い
