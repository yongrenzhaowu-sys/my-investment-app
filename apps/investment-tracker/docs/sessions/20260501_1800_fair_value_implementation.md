## 📊 実装した機能の詳細

### グロース株評価の流れ

```
1. EPS成長率分析
   ├─ 過去CAGR計算（異常値除外）
   ├─ 予想成長率取得
   └─ 採用成長率決定 → 成長率帯判定（low/mid/high/ultra）

2. 成長品質評価（4指標）
   ├─ 売上成長（5%以上）
   ├─ 利益率改善（1%ポイント以上）
   ├─ 一時要因依存度（異常値年の割合）
   └─ EPS安定性（変動係数0.5未満）
   → スコアリング（0～4点） → ランク判定（high/medium/low）

3. PEGレシオ決定
   └─ マトリクス参照（成長率帯×品質ランク）→ PEGレンジ → 中央値採用

4. 適正PER算出
   ├─ 理論PER = PEG × 成長率（%値）
   └─ 調整後PER = min(理論PER, 過去上限 × 1.2)

5. 株価レンジ算出
   ├─ 保守: 今期EPS × 採用PER
   ├─ 中央: 来期EPS × 採用PER
   └─ 強気: 再来期EPS × 採用PER

6. 評価判定
   └─ 乖離率 = (現在株価 - 中央ケース) / 中央ケース × 100
      ├─ 乖離 ≤ -15%: 割安
      ├─ 乖離 ≥ +15%: 割高
      └─ その他: 適正
```

### バリュー株評価の流れ

```
1. 正規化EPS算出
   └─ 優先順位: 来期予想EPS > 今期EPS > 過去平均EPS

2. 品質評価（4軸）
   ├─ 資産品質（現預金比率、のれんリスク、棚卸資産リスク）
   ├─ 財務安全性（自己資本比率、ネットキャッシュ、CF安定性）
   ├─ ROE水準（低<5%, 中5-10%, 高>10%）
   └─ 還元姿勢（配当利回り: 弱<1%, 普通1-3%, 積極>3%）
   → 総合品質ランク（high/medium/low）

3. 評価軸選定
   ├─ ROE高 → PER方式
   ├─ 低ROE・高現預金 → PBR方式
   ├─ 財務安全性高・収益安定 → PER方式
   └─ デフォルト → PBR方式

4. マルチプル算出
   └─ マトリクス参照（ROE水準×品質ランク または 品質ランクのみ）
      → マルチプルレンジ → 中央値採用 → 過去上限調整

5. 株価レンジ算出
   ├─ PBR方式: BPS × 採用PBR × (0.9 / 1.0 / 1.1)
   └─ PER方式: 採用EPS × 採用PER × ケース別係数

6. 評価判定
   ├─ 乖離率計算
   ├─ 安全域 = (中央ケース - 現在株価) / 中央ケース × 100
   └─ 判定（割安/適正/割高）
```

## 🔧 技術的な決定事項

### 1. データモデル設計

**採用: dataclass**
- 理由: 不変データ構造、フィールド明示、型ヒント統合
- メリット: IDEの補完強化、コード可読性向上
- デメリット: 継承が複雑（今回は単純な構造で回避）

### 2. 計算ロジック設計

**採用: 純関数 + reasonsリスト**
- 理由: 副作用なし、テストしやすい、計算過程を記録
- メリット: デバッグ容易、監査可能、再現性高い
- デメリット: 状態管理が必要な場合は別途設計（今回は不要）

### 3. マトリクス駆動設計

**採用: 定数モジュール + ヘルパー関数**
- 理由: ビジネスロジックとコード分離、変更容易
- メリット: ルール変更時にコード修正不要、テストデータとして利用可能
- デメリット: 定数ファイルの肥大化（今回は許容範囲）

### 4. エラーハンドリング戦略

**採用: フォールバック値 + warningログ**
- 理由: データ欠損が頻発する環境、完全なデータは期待できない
- メリット: 部分データでも計算可能、ユーザー体験向上
- デメリット: サイレントエラーのリスク（reasonsで明示して回避）

### 5. UI統合方法

**採用: タブUI（新機能メイン、旧機能サブ）**
- 理由: ユーザーの要望「既存機能を置き換え」に対応
- メリット: 既存機能も残しつつ、新機能を強調
- デメリット: 画面遷移が増える（タブ2つで許容範囲）
