## 🎯 問題の発見

### 現象
- セクター強弱判定機能で**22業種のみ取得**され、33業種中11業種が欠落
- ユーザーから「22業種だけしか取得できていないのも気になる」と指摘

### 原因調査

1. **公式ドキュメント確認**

2. **テストスクリプトでの検証**

   - 0040〜0072の全コードでAPI呼び出しテスト

### 根本原因

**現在の実装（誤り）**:
```python
# 10進数前提で 0050, 0051, ..., 0072 を定義
SECTOR_33_CODES = {
    "0050": "ガラス・土石製品",  # ❌ 誤り
    "0051": "鉄鋼",              # ❌ 誤り
    ...
    "0072": "サービス業"          # ❌ 誤り
}
```

**正しい実装（16進数）**:
```python
# 16進数コード体系
SECTOR_33_CODES = {
    "004A": "ガラス・土石製品",  # ✅ 正しい（A=10）
    "004B": "鉄鋼",              # ✅ 正しい（B=11）
    ...
    "0060": "サービス業"          # ✅ 正しい
}
```

| 004A-004F | 6 | ガラス・土石製品 〜 電気機器（A=10, F=15） |

### 16進数の理解

- `004A` = 0x004A = 74（10進数）
- `004F` = 0x004F = 79（10進数）
- `005A` = 0x005A = 90（10進数）
- `005F` = 0x005F = 95（10進数）
- `0060` = 0x0060 = 96（10進数）

## 🔧 技術的な学び

### 1. J-Quants APIの指数コード体系

- **16進数コード体系を採用**
- 0-9（数字）とA-F（16進数）を組み合わせて連続コードを表現
- 理由: おそらくAPIの内部実装で16進数を使用

### 2. Pythonでの16進数リテラル

```python
# リテラル表記
hex_code = 0x004A  # 74（10進数）

# 文字列から変換
int("004A", 16)  # 74

# 16進数文字列の生成
f"{74:04X}"  # "004A"
```

### 3. ソート順序

```python
# 文字列として辞書順ソート
sorted(["0040", "004A", "0050"])
# → ["0040", "004A", "0050"]（正しい16進数順）

# ❌ 数値としてソートすると誤り
sorted(["0040", "0050", "004A"])  # 誤った順序
```
